# *Core Processes Matrix:*

| Process No. and Name | Input Data | Output Data | Rules |
|---|---|---|---|
| P1 – Manage User Accounts | Login Credentials and Registration Details (from Patient)<br>Patient Account Details (from Patient & Prescription Data) | Login Result and Registration Confirmation (to Patient)<br>Patient Account Data (to Patient & Prescription Data)<br>Authenticated User Details (to P2 and P3) | Login is granted only if the credentials match a stored account, otherwise the Login Result is a failure. Registration requires all mandatory fields (name, contact information, date of birth), and the contact information must not already belong to an account. A successful registration or login always returns a confirmation or result to the patient. Only authenticated users are passed to P2 and P3, and personal data is stored in encrypted form. |
| P2 – Manage Refill Requests | Refill Request and View Active Prescriptions (from Patient)<br>Authenticated User Details (from P1)<br>Eligibility Decision, View Refill Request, Update Next Stage and Mark Refill Ready for Pickup (from Pharmacy Staff)<br>Refill/Request Details (from Refill & Inventory Data) | Eligibility Details, Refill Request Details and Status/Pickup Order Information (to Patient)<br>Incoming Refill Request Details and Refill Status History (to Pharmacy Staff)<br>Refill Status Change and Status Pickup Location (to P4)<br>Refill Request/Status Data (to Refill & Inventory Data) | A refill request is accepted only from an authenticated patient. The prescription must belong to that patient, be active, and have refills remaining. The minimum waiting period since the last refill must have passed. Only pharmacy staff can give the Eligibility Decision, and a rejection must include a reason. A request moves through its stages in order and cannot skip one. Every status change is saved in the refill status history and sent to P4 for notification. |
| P3 – Manage Prescriptions | View Active Prescriptions (from Patient)<br>Authenticated User Details (from P1)<br>New Prescription Data, Edit Prescription Data and Search Patient Records (from Pharmacy Staff)<br>Patient + Prescription Records (from Patient & Prescription Data) | Active Prescription Details (to Patient)<br>Patient Records (to Pharmacy Staff)<br>New/Updated Prescription Data (to Patient & Prescription Data) | Only pharmacy staff can create, edit or search prescriptions and patient records. A prescription must be linked to a registered patient. An edit must keep the prescription valid, for example the number of refills cannot be negative. A patient can only view their own active prescriptions, and expired prescriptions are not shown as active. |
| P4 – Notification Alerts | Refill Status Change and Status Pickup Location (from P2)<br>Low Stock Condition (from P5) | Refill Status Notification and Inform Pickup Location (to Patient)<br>Low Stock Alert (to Pharmacy Staff) | A notification is sent every time a refill request status changes. Notifications go only to the patient who owns the request. The pickup location is sent only after the order has been marked ready for pickup. A Low Stock Alert is sent to Pharmacy Staff whenever P5 reports a low stock condition. Notifications must be delivered within 30 seconds of the status change. |
| P5 – Manage Inventory | Inventory Stock Update (from Pharmacy Staff)<br>Inventory/Stock Levels (from Refill & Inventory Data) | Inventory Stock Information (to Pharmacy Staff)<br>Inventory Update (to Refill & Inventory Data)<br>Low Stock Condition (to P4) | Only pharmacy staff can update stock. Quantities can never go below zero. Stock is deducted when a refill is accepted and fulfilled. If a medication's quantity falls below the threshold, a Low Stock Condition is sent to P4. The threshold can be changed by pharmacy management without changing the code. |
