# *Selected Workflows for Activity Modeling:*

| Use Case ID | Use Case Name | Swimlanes | Main Workflow | Decisions (Guards) | Fork / Join | Activity Diagram | Contributor |
|---|---|---|---|---|---|---|---|
| UC-01 | Input Refill Request | Patient, System | The patient views their active prescriptions, selects one and submits a refill request. The system creates the request and checks its eligibility. If eligible, the status is set to PENDING, the status history is recorded and a confirmation is shown. Otherwise the reason is shown. | [eligible] / [not eligible] | Recording the status history and showing the confirmation run in parallel. | AD_UC01_Input_Refill_Request.pdf | Dima |
| UC-02 | Login | User (Patient / Pharmacy Staff), System | The user enters their credentials. The system authenticates them and checks their permission. If both succeed, a session is created and the login is logged and confirmed. Invalid credentials and denied access are logged and shown. A failed login can be retried up to 3 times. | [valid] / [invalid], [granted] / [denied], [login failed and attempts < 3] / [logged in or attempts = 3] | Logging the successful login and showing the success message run in parallel. | AD_UC02_Login.pdf | Yuchang |
| UC-13 | Update Inventory Stock | Pharmacy Staff, System | The staff member selects an item and enters the new quantity. The system validates it and updates the stock, then checks the low stock threshold. If stock is low, a low stock alert is created and sent to pharmacy staff (UC-14 extends UC-13). An invalid quantity shows an error. | [newQty >= 0] / [newQty < 0], [low stock] / [not low stock] | Staff receiving the low stock alert and the system showing the stock update run in parallel. | AD_UC13_Update_Inventory_Stock.pdf | Maryam |
| UC-17 | Mark Refill as Ready for Pickup | Pharmacy Staff, System | The staff member selects a refill request, views its details and marks it ready. The system checks the status. If it is PREPARING, the status is set to READY_FOR_PICKUP, the status history is recorded, a pickup order is created with the pickup location, and the patient is notified. Otherwise the change is not allowed. | [status == PREPARING] / [status != PREPARING] | None. The steps follow the order of the sequence diagram. | AD_UC17_Mark_Refill_Ready_For_Pickup.pdf | Haya |
